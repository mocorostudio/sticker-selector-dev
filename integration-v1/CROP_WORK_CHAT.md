# Work／チャット共通の切り出し・透過前処理

制作ルールv10・制作手順書v3と対象最新マスターを接続済みDriveから本文取得して使う。画像生成・本番選抜の変更・合格判定は、このコマンドでは行わない。

## 実行入口

developmentの本リポジトリを取得し、Workでもチャットでも同じコマンドを使う。

```sh
python3 scripts/crop-stickers.py INPUT.json NEW_OUTPUT_DIR
```

Python/PillowとNode.js 18以降が必要。Pythonが別の場所にある場合は `CODEX_PRIMARY_RUNTIME_PYTHON`、Nodeが別の場所にある場合は `CODEX_PRIMARY_RUNTIME_NODE` を指定する。追加課金・有料API・新しい画像生成は使わない。実行環境に必要な機能がなければ止まり、別の未検証アルゴリズムで代用しない。ユーザーに端末操作やZIPのダウンロードを依頼せず、担当AIが実行する。

Python入口はNodeコマンドを起動するだけ。背景処理は既存アプリの `crop-v9/transparency.mjs`、独立セルの抽出は既存 `component-crops.mjs` を共有する。Pythonの `crop-pixels.py` はPNG入出力と、既存 `placementPlan` が決めた寸法への画像配置だけを担当し、別の透過アルゴリズムは持たない。

処理順は、元画像全体の透過前処理 → 既存の連結成分によるセル分離 → セルの透過前処理 → 370×320配置 → 実PNG再読込・機械確認・ハッシュ記録。アプリの新規一括切り出しも、同じ元画像前処理を通る。元画像を直接書き換えない。Workとチャットのコマンド出力は同じPillow経路。ブラウザのサイズ調整は従来のCanvas経路を保持するため、ブラウザとCLIのリサイズ後PNGがバイト一致するとは扱わない。

## INPUT.json

担当AIが取得済みの実データから作成する。正本取得の代わりになるファイルではない。

```json
{
  "schema": "animal-stickers-crop-input/v1",
  "characterId": "取得したキャラフォルダID",
  "masterReference": "https://docs.google.com/spreadsheets/d/取得したマスターID/edit",
  "masterSheet": "取得した対象シート名",
  "masterModifiedTime": "取得した更新日時",
  "master": [
    {"candidateId": "GDA001", "phrase": "取得した正確なセリフ", "pose": "取得した正確なポーズ"}
  ],
  "batches": [
    {
      "batchId": "B01",
      "sourceFileId": "取得した元画像DriveファイルID",
      "path": "sources/B01.png",
      "sha256": "取得した元PNGのSHA256",
      "candidateIds": ["GDA001", "GDA002", "GDA003", "GDA004", "GDA005", "GDA006", "GDA007", "GDA008", "GDA009"]
    }
  ]
}
```

例はフィールド説明。実行時は全マスター行と全バッチを揃える。81候補ならmaster81行・9バッチ。候補の順序は元画像の左上から行優先で、実画像と照合した対応を指定する。ID・文言・ポーズ・バッチの欠落／重複、元PNGハッシュ不一致、入力フォルダ外へのパス、出力先の既存ディレクトリは拒否する。

## 出力と検品引き継ぎ

- 候補ごとのRGBA PNG。旧ファイルは上書きせず、新しい試行IDを付ける。
- `crop-result.json`：全候補の画像ID・候補ID・セリフ・ポーズ・元画像ID／バッチID／ハッシュ・出力ハッシュ・除去画素数・処理版・未解決事項・機械検査結果。
- 途中失敗は `execution-failed.json` に完了候補と失敗理由を残し、依存範囲の処理を止める。

出力は個別目視検品前のため、全候補をhold／要確認として記録し、passは付けない。チャット担当が元画像と1枚ずつ照合してpass／hold／fail・理由を確定する。数値検査だけで一括合格にしない。

微弱アルファと外周からつながる低彩度の半透明残留は実際に除去する。白い本体・文字白フチ・水彩縁を守り、不透明な白背景や輪郭に接する残留を一律に白抜きしない。安全に分離できない背景・セルは未完了として止め、完全透過済みと呼ばない。

検品後は制作手順書21節の既存Drive直接引き渡しを使う。全候補の確認表示と正式な技術承認は別。`crop-result.json` 自体は選抜アプリの読込manifestではない。既存の選抜・順番・メイン／タブ・編集内容を自動加工／置換しない。保存済み一式の検品や申請用ZIP作成を、この修正のためにやり直す必要はない。

## 最終PNGの背景残留防止（2026-11-07）
元画像の前処理だけで透過済みと判断しない。Work/chat共通コマンドとアプリは縮小後の画素にも既存の安全な透過処理を再実行する。検品は実画素の微弱アルファ・境界につながる白い膜を検出し、以前のpass記録だけで通過させない。
選抜保存では40枚と最新メイン・タブの最終PNGを再処理・再デコードして確認する。選抜元画像、候補ID、好みの判定、コメント、編集は変更しない。修正したPNGは派生出力として元ハッシュ・処理結果・出力ハッシュを記録する。透過修正は技術合格への昇格ではなく、確認用一式として保存する。水彩や白い本体を壊す一括の白抜き・強いアルファ閾値は使わない。不透明背景を安全に判断できない場合は停止する。
