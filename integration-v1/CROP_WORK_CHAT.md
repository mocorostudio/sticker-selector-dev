# Work／チャット共通の切り出し・透過前処理

制作ルールv10・制作手順書v3と対象最新マスターを接続済みDriveから本文取得して使う。画像生成・本番選抜の変更・合格判定は、このコマンドでは行わない。

## 実行入口

developmentの本リポジトリを取得し、Workでもチャットでも同じコマンドを使う。

```sh
python3 scripts/crop-stickers.py INPUT.json NEW_OUTPUT_DIR
```

Python/PillowとNode.js 18以降が必要。Pythonが別の場所にある場合は `CODEX_PRIMARY_RUNTIME_PYTHON`、Nodeが別の場所にある場合は `CODEX_PRIMARY_RUNTIME_NODE` を指定する。追加課金・有料API・新しい画像生成は使わない。実行環境に必要な機能がなければ止まり、別の未検証アルゴリズムで代用しない。ユーザーに端末操作やZIPのダウンロードを依頼せず、担当AIが実行する。

Python入口はNodeコマンドを起動するだけ。背景処理は既存アプリの `crop-v9/transparency.mjs`、独立セルの抽出は既存 `component-crops.mjs` を共有する。Pythonの `crop-pixels.py` はPNG入出力と、既存 `placementPlan` が決めた寸法への画像配置だけを担当し、別の透過アルゴリズムは持たない。

処理順は、元画像全体の透過前処理 → 既存の連結成分によるセル分離 → セルの透過前処理 → 370×320配置 → 実PNG再読込・機械確認・ハッシュ記録。アプリの新規一括切り出しも、同じ元画像前処理を通る。元画像を直接書き換えない。Workとチャットのコマンド出力は同じPillow経路。ブラウザのサイズ調整は従来のCanvas経路を保持するため、ブラウザとCLIのリサイズ後PNGがバイト一致するとは扱わない。

## INPUT.json

担当AIが取得済みの実データから作成する。正本取得の代わりになるファイルではない。

```json
{
  "schema": "animal-stickers-crop-input/v1",
  "characterId": "取得したキャラフォルダID",
  "masterReference": "https://docs.google.com/spreadsheets/d/取得したマスターID/edit",
  "masterSheet": "取得した対象シート名",
  "masterModifiedTime": "取得した更新日時",
  "master": [
    {"candidateId": "GDA001", "phrase": "取得した正確なセリフ", "pose": "取得した正確なポーズ"}
  ],
  "batches": [
    {
      "batchId": "B01",
      "sourceFileId": "取得した元画像DriveファイルID",
      "path": "sources/B01.png",
      "sha256": "取得した元PNGのSHA256",
      "candidateIds": ["GDA001", "GDA002", "GDA003", "GDA004", "GDA005", "GDA006", "GDA007", "GDA008", "GDA009"]
    }
  ]
}
```

例はフィールド説明。実行時は全マスター行と全バッチを揃える。81候補ならmaster81行・9バッチ。候補の順序は元画像の左上から行優先で、実画像と照合した対応を指定する。ID・文言・ポーズ・バッチの欠落／重複、元PNGハッシュ不一致、入力フォルダ外へのパス、出力先の既存ディレクトリは拒否する。

## 文字保存を優先する透過処理（2026-11-10）

最新版の制作ルールv10第4節・制作手順書v3第24節を優先する。生成後の文字の色変更・白フチの細線化・削除・追加・再構築は禁止。文字と絵の重なりも加工しない。別のPythonやその場の正規化スクリプトで補修しない。

`safe-transparency/v4-preserve-lettering` は、確認指定のないRGBAをそのまま保持する。薄さ、白さ、距離、成分面積だけでは削除しない。背景らしい画素は保持してholdにし、元画像との個別比較へ回す。文字を自動認識しているわけではない。

### 確認領域の指定

担当AIが元画像を拡大して背景と確認できた分離領域に限り、各batchへ次を記録できる。取得元SHA256照合後に共通処理を実行する。数値や範囲の例を実画像へ流用しない。

```json
{
  "reviewedBackground": {
    "kind": "reviewed-background-regions/v1",
    "regions": [[0, 0, 100, 100]],
    "reason": "実画像で確認した背景位置と根拠"
  },
  "protectedForeground": {
    "kind": "protected-foreground-regions/v1",
    "regions": [[30, 30, 80, 80]],
    "reason": "文字全体・白フチ・絵との重なりを含む保護範囲"
  }
}
```

regionsは元画像実寸内の整数 `[x0,y0,x1,y1]`、右端・下端を含まない。保護指定が背景指定と重なれば保護を優先する。保護範囲のRGBAと、確認済み背景領域以外のRGBAを処理前後で比較し、1チャンネルでも変われば停止する。範囲・理由が不正な入力も停止する。

背景指定内でも不透明な芯・周囲3pxを守り、低アルファ背景だけを除去する。分離できない残留は保持してholdにする。指定があること自体を技術合格の根拠にしない。

確認領域は元画像の座標専用。セルや縮小後へ同じ座標を流用しない。セル分離は小さな句読点や弱い孤立成分も回収し、帰属が曖昧なら保留する。元画像段階で確認済みの除去を終え、セル・配置後の処理は確認指定がない限りRGBAを削除・色変更しない。通常のリサイズによる補間は許可されるが、縮小後に文字色や縁を整形しない。

ブラウザの単色一括削除も停止する。既存端末の選抜・順番・コメント・メイン／タブ・未保存操作を移行・上書きしない。

## 保存・検品・引き渡し

- 全候補を新試行IDのRGBA PNGとして保存し、旧ファイルを上書きしない。
- `crop-result.json` に元画像SHA256、候補対応、確認領域・理由、処理版、除去数、保持・未解決事項、数値判定を記録する。
- 配置後の透過処理前後と、最終PNG保存・再読込前後の全RGBAを比較する。リサイズ前後のバイト一致とは区別する。
- `_background-review.png` は最終PNGと同じ画素を白・濃紺・黒背景に合成した検品用資料。申請ZIPへ含めない。
- 失敗時は `execution-failed.json` に完了候補と理由を残し、依存範囲を停止する。

全候補は個別目視前のholdとして出力する。PNG数値検査のverifiedを正式合格と呼ばない。担当AIが元画像と1枚ずつ、文字内外・白フチ・重なり・四隅・外周・装飾を照合して技術判定する。透明表示と実アルファを区別し、半透明があるだけで不合格にしない。

残留疑いを消すために文字を削ることは禁止。安全な背景指定でも除去できなければ画像を保持して保留する。最終PNGに対する追加背景除去も `finalizeTransparency` の同じ確認領域契約を使い、独自処理を作らない。保存後の全RGBAが想定画素と異なれば停止する。Canvasの丸め差を理由に文字変更を許容しない。

技術検品後のDrive直接引き渡しと選抜テストは、制作ルール第12節・手順書第15節・第21節を別途適用する。このコマンドの結果は選抜アプリのmanifestではなく、本番選抜を自動置換しない。
