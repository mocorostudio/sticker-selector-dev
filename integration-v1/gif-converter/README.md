# GIF to LINE APNG
Standalone browser-only tool. Open index.html through an HTTP server. No upload service, API key, paid API or CDN is used. gifuct-js 2.1.2 (MIT) decodes GIF; fflate 0.8.2 (MIT) compresses RGBA frames and ZIP. Licenses are included. Vendor bundle was built with esbuild 0.25.12 from exports parseGIF/decompressFrames and zlibSync/zipSync/strToU8.

Original GIFs are retained in IndexedDB. Order, archived IDs, first-frame choice and global settings persist in localStorage. Reload recomputes output and requires fresh visual confirmation; source files remain available. Removing from the list archives without deleting original bytes. Capacity/private-browsing restrictions are reported. GIF decoder supports disposal methods 0–3; full composited frames are sampled by original timing. APNG frames are full-canvas RGBA, SOURCE blending, no disposal, finite play count, exact rational delays, CRC-checked.

Exports are individually re-parsed for dimensions, CRC, frame count, sequences, duration, loops and size. ZIP export requires 8/16/24 outputs, per-item visual acknowledgement and explicit main/tab selection and crop confirmation. Main is animated 240×240; tab is static 96×74. Output is fitted with 8px padding, preserving the complete source canvas. Background removal, content/rights review and LINE submission are not performed. Oversize output is blocked rather than silently quantized. The 1MB and 60MB limits are enforced conservatively as decimal bytes.

Source of specification, checked 2026-11-16:
- https://creator.line.me/ja/guideline/animationsticker/
- https://creator.line.me/ja/guideline/animationsticker/detail/

Run: node --test integration-v1/gif-converter/codec.test.mjs
Browser QA: 3 synthetic transparent GIFs using disposal 1/2/3; batch conversion; downloaded APNG independently read with Pillow; source restoration on reload; 8-file ZIP path. No production images or Drive records modified. iPhone hardware and LINE upload remain separate checks.

## Alpha and transparency update (2026-11-16)

Inputs: animated GIF/APNG, or a naturally sorted sequence of matching-size static PNG files. PNG/APNG uses vendored UPNG.js 2.1.0 + pako (MIT), retaining 8-bit RGBA, with an explicit compositor for APNG SOURCE/OVER and NONE/BACKGROUND/PREVIOUS disposal. 16-bit PNG is rejected with a conversion explanation. Header geometry, chunk CRCs, sequence numbers, frame rectangles and memory budget are checked before decoding. Original files remain in the existing IndexedDB store; legacy GIF records are read without migration. New background-processing revisions append full processed source frames and source-bound preservation reports; original files and old revisions are retained. No source images are sent to a server.

The review dialog plays all frames on white, black and checker backgrounds with a synchronized timeline, pause/scrub, original/current/output/candidate switch, and a frame-by-frame findings list. Numeric findings include all 256 alpha bins, detached semitransparent components, enclosed transparent areas, abrupt area changes, retained prior-frame pixels with area growth (trail suspicion), and selected-background-color matches. These are suspicions, including natural white bodies, decorations and letter holes; no automatic pass is issued. Animation semantics and fine fur/eyes/mouth are explicitly marked as requiring visual review.

Opaque-background removal is a conservative extension of the existing shared `crop-v9/transparency.mjs`, not an unrelated color-key pipeline. An operator must mark protective foreground rectangles spanning all poses and select an opaque exterior background color. Only exact matching opaque pixels connected to the outer image boundary inside reviewed background can be removed. Foreground protection, a three-pixel guard around every non-background feature, semitransparent edges, enclosed areas and all unmatched pixels remain unchanged. An independent guard checks all protected/unreviewed pixels. This intentionally leaves ambiguous fringes and matching-color regions for review; it is not semantic segmentation or an automatic watercolor cutout guarantee. New internal holes reject the candidate. Applying a candidate creates a new history revision, invalidates downstream output and cover approval, and retains originals.

Conversion does not establish transparency. A colored opaque input is labeled background-removal-required even after fitting creates transparent padding. Unreviewed exports are named `NN_要確認.png`; final numbered exports/ZIP require explicit visual review, no unresolved fully opaque source frame and the preexisting structural requirements. Format validity and operator visual review are separate. After encoding, each full RGBA frame is decoded again and CRC-compared with the intended frame data; output remains animated RGBA APNG with `.png` extension. The explicit fit/resampling step may change pixel positions/edge alpha as normal resizing does; it does not apply alpha cutoffs or RGB quantization.

Validation: 32 targeted new/existing tests passed, including 256 alpha values, tiny semitransparent features, white bodies/eyes/mouth/whiskers, enclosed holes, trails, APNG blend/disposal, protected pixel conservation and corrupt input rejection. Independently decoded a mixed-disposal/mixed-blend APNG with FFmpeg: alpha bytes identical, RGB within rounding 1. Browser-tested APNG and opaque GIF input, numeric PNG sequence ordering, simultaneous three-background review, conservative background candidate/apply, history/source restoration, and downloaded animated PNG readback. Input APNG comparison against Pillow was not used as a compositing oracle for partial-alpha OVER; full-frame SOURCE output is separately read with Pillow. iPhone hardware and LINE submission remain unverified.
