# Work-efficient crop workflow

Use the existing crop-v9 batch processor for automatic cropping and pixel checks. Preserve its per-item persistence for recovery. Do not repeat full regression suites for each image batch unless code or environment changes. Keep visual inspection, candidate-master matching, and formal handoff gates separate from draft selection. Never report draft transfer as technical approval or verified Drive saving.

This document does not change runtime behavior or existing data.

## Per-image visual report import (2026-11-04 continuation)

The technical-inspection dialog now offers a detailed JSON report import. This is an operator-facing advanced path, not a new user production step. `inspection-report.mjs` accepts up to 130 separate decisions and performs preflight for every entry before a single state save. It checks exact imageId, inspectionIdentity, PNG SHA-256, explicit nine boolean checks, reviewer, reviewedAt and decision/reason. Machine QA is computed by the existing inspector. It never assigns candidates or promotes formal eligibility. Fail/review revoke existing formal eligibility as in individual inspection. Votes, comments, crop data, artwork edits and user history are untouched. Same report retry adds no history or save; save failure restores all modified fields.

Report shape: `{schema:"animal-stickers-visual-report/v1",reviewer:"reviewer identifier",entries:[{imageId,identity,sha256,reviewedAt,decision,checks,comment}]}`. identity is the exact `inspectionIdentity(item)` string; checks follow exported visualChecks order. Decisions must result from actual visual inspection of the exact PNG; neither an all-pass template nor machine QA is visual evidence. A mixed pass/review/fail report is supported. Candidate mapping must already be staged against the latest master; this import does not replace live-master checks at formal registration. No artwork report was fabricated or applied during development.

For 81 candidates, this replaces up to 81 individual inspection-save actions with one report import (plus one file selection). Visual review, nine-cell master mapping and grouped formal Drive registration remain required. Actual Work quota savings have not been measured. Test fixtures use synthetic pixel buffers; browser wiring, real artwork, authenticated Drive, deployment and iPhone are not certified by these Node tests.

## Bulk formal registration (2026-11-04)

`bulk-formal.mjs` and the workflow's advanced file input now accept `animal-stickers-bulk-formal/v1` jobs: `{schema,characterId,assignments:[{imageId,candidateId,batchId,slot}],visualReport?}`. Nine complete cells are required per explicit batch; up to 126 candidates fit the 130-entry safety limit. The optional visualReport uses the individual-report schema above and must cover exactly the assigned image IDs. Each candidate's phrase/pose comes from the one freshly fetched live master; image-to-candidate/slot association is always explicit. A candidate assignment alone cannot create approval.

The operator can submit all nine batches and all individual visual decisions in one file instead of operating 81 inspection controls and nine mapping dialogs. The job stages assignments and visual decisions on cloned state, reuses the existing audited sender, strict nine-cell manifest builder, PNG decoder/pixel gate, exact-byte stored-image check and verified handoff. Every batch must succeed before one local state save. Existing votes, comments, artwork edits and histories survive; concurrent edits abort the commit and stay intact. Same job retry adds no save or registration history. No PNG rewriting, remote uploading, paid service or new storage target was introduced. Drive registration remains the existing grouped save action with per-PNG recovery and ID/hash readback. Single-batch message handling also reuses its freshly fetched master within that same operation instead of fetching it twice.

Verification: 81 candidates across nine batches use one master read and one state save in the isolated Node fixture. Retry uses one fresh master read and zero state saves. Tests reject duplicate slots, incomplete batches, missing audit/PNG, incomplete visual checks and wrong character before changing original state. They also exercise combined assignment/report input, save rollback and preservation of concurrent user edits. Fixtures contain CRC-valid synthetic RGBA PNG bytes; their deterministic decoder is a test substitute, not browser or artistic verification. The related targeted suite passed 82 checks; browser UI, real artwork end-to-end, authenticated Drive, deployed page and iPhone remain unverified because the browser executable is absent.

Expected operator orchestration for 81 candidates: one grouped input acquisition, one crop run, visual inspection of the nine sheets plus flagged individual details, one combined job import, one grouped Drive save/readback. Batch mapping is represented explicitly in the job rather than guessed. These are stages, not a measured Work percentage or guaranteed browser-click count. A production report must only contain decisions actually made from the exact PNGs; no report for real artwork was created in this development task. User participation stays selection, main/tab, final adoption and any indispensable Google sign-in; advanced report preparation/import is the assistant/operator's task.
